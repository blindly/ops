CLI Reference

ops run

Run a job file against remote servers, or on the local machine with --local. If no job file is given, defaults to jobs.yaml in the current directory.

terminal
$ ops run [job-file] [flags]

Example:

terminal
$ ops run jobs.yaml -s servers.yaml --workers 5
TASK         SERVER   STATUS   EXIT   DURATION
uptime       web1     ok       0      85ms
uptime       web2     ok       0      92ms
disk usage   web1     ok       0      67ms
disk usage   web2     ok       0      71ms

── uptime [web1] ──
 12:34:56 up 1 day,  3 users,  load average: 0.12, 0.15, 0.10

── disk usage [web1] ──
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda1        50G   23G   25G  48% /

── uptime [web2] ──
 12:34:56 up 5 days,  1 user,  load average: 0.08, 0.10, 0.05

── disk usage [web2] ──
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda1        50G   18G   30G   38% /

Started: 2026-08-15T11:20:30-04:00
Duration: 320ms

Pass --local to run the job on the current machine without SSH.

Pass --dry-run to print the planned commands, scripts, and uploads without executing anything.

terminal
$ ops run jobs.yaml --dry-run
TASK         SERVER   STATUS   PLAN
say hello    web1     plan     command: echo "hello world"
show shell  web1     plan     shell: 42 bytes

ops plan is an alias for ops run --dry-run and does not require servers.

terminal
$ ops plan jobs.yaml
TASK         SERVER   STATUS   PLAN
say hello    -        plan     command: echo "hello world"

ops update

Check for and install the latest release from GitHub.

terminal
$ ops update
Current version: <version>
Latest version:  <version>
Downloading ops-linux-amd64...
Installing...
Updated to <version>.

Check without installing:

terminal
$ ops update --check
Current version: <version>
Latest version:  <version>
Update available. Run without --check to install.

Install even if the current version already matches the latest:

terminal
$ ops update --force
Current version: <version>
Latest version:  <version>
Downloading ops-linux-amd64...
Installing...
Updated to <version>.

Update from a different GitHub repo:

terminal
$ ops update --repo yourorg/ops

ops version

Print the current version.

terminal
$ ops version
<version>

ops new

Create a starter jobs.yaml and servers.yaml in the given directory. Defaults to the current directory. Existing files are not overwritten.

terminal
$ ops new my-project
created sample files:
  my-project/jobs.yaml
  my-project/servers.yaml

ops validate

Validate a job file without executing it. Checks YAML structure, required fields, and that each task has a command, script, or shell. Defaults to jobs.yaml in the current directory.

terminal
$ ops validate [job-file]

Example:

terminal
$ ops validate jobs.yaml
valid

ops list

List YAML job files in the current directory, showing each file and description. Non-job YAML files are skipped.

Alias: ls

Use -r or --recursive to search subdirectories. Hidden directories, node_modules, and vendor are skipped.

terminal
$ ops ls -r
PATH                DESCRIPTION
examples/jobs.yaml  install and restart nginx
terminal
$ ops list
FILE        DESCRIPTION
jobs.yaml   install and restart nginx

Flags

Flags for ops run:

FlagShortDefaultDescription
--servers-sPath to a servers YAML file.
--server-list-SComma-separated inline server aliases.
--ssh-config~/.ssh/configPath to SSH config file.
--env-eEnvironment variables (key=value, repeatable).
--varJob variables (key=value, repeatable).
--workers-w10Concurrency: number of parallel SSH connections.
--quiet-qfalseSuppress command output; show summary table only.
--output-otextOutput format: text or json. Text mode shows stdout/stderr per task.
--streamfalseStream command output live as each task runs. Only compatible with text output.
--keepfalseDo not remove uploaded scripts after execution.
--fail-fastfalseStop all tasks on first failure.
--insecure-ignore-hostkeyfalseSkip host key verification. Insecure — testing only.
--localfalseRun tasks on the local machine without SSH.
--dry-runfalsePrint planned commands, scripts, and uploads without executing.

Examples

Run with inline servers

terminal
$ ops run jobs.yaml -S web1,web2,db1

Run with JSON output for CI

terminal
$ ops run jobs.yaml -o json | jq '.tasks[] | select(.ExitCode != 0)'

Run with variables and env

terminal
$ ops run jobs.yaml \
    --var version=1.25 \
    --var domain=prod.example.com \
    -e DEBIAN_FRONTEND=noninteractive

Run with fail-fast and custom workers

terminal
$ ops run jobs.yaml --fail-fast --workers 3

Run with a custom SSH config

terminal
$ ops run jobs.yaml --ssh-config ~/.ssh/config.staging

Keep uploaded scripts for debugging

terminal
$ ops run jobs.yaml --keep --insecure-ignore-hostkey

Run quietly (summary only)

terminal
$ ops run jobs.yaml -q
TASK         SERVER   STATUS   EXIT   DURATION
uptime       web1     ok       0      85ms
uptime       web2     ok       0      92ms
disk usage   web1     ok       0      67ms
disk usage   web2     ok       0      71ms

Started: 2026-08-15T11:20:30-04:00
Duration: 320ms
Exit code: ops exits with the highest remote exit code, or 1 if any connection failed. This makes it CI-friendly — a non-zero exit signals failure.
