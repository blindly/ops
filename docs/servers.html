Servers

ops does not maintain its own inventory of connection details. Instead, it reads server aliases from a simple YAML file and resolves them against your ~/.ssh/config. If ssh web1 works, ops can reach web1.

servers.yaml

A servers file is just a list of Host aliases that exist in your SSH config:

servers.yaml
servers:
  - web1
  - web2
  - db1
  - win1

Reference it from a job:

jobs.yaml
---
description: my job
servers: ./servers.yaml
tasks:
  - name: ping
    command: echo pong

SSH Config

Each alias in servers.yaml must match a Host block in your SSH config, with one exception: the reserved alias local runs on the current machine without SSH. ops reads HostName, User, Port, and IdentityFile from the matching block:

~/.ssh/config
Host web1
    HostName 10.0.0.5
    User admin
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host web2
    HostName 10.0.0.6
    User admin
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host db1
    HostName db.internal
    User ubuntu
    Port 2222

Host win1
    HostName 10.0.0.7
    User Administrator
    IdentityFile ~/.ssh/win-key

Resolution Rules

  • Default config file is ~/.ssh/config
  • Override with --ssh-config <path> or OPS_SSH_CONFIG env var
  • HostName defaults to the alias itself if not specified
  • User defaults to the current OS user if not specified
  • Port defaults to 22 if not specified
  • IdentityFile is passed to the SSH client for key-based auth
  • Wildcard Host patterns are not expanded — aliases must be explicit
  • Port must be a valid integer in the range 1–65535
Auth methods: ops supports SSH key files, ssh-agent, and password (via SSH_PASSWORD env var). Host key verification uses ~/.ssh/known_hosts by default. Use --insecure-ignore-hostkey only for testing.

Inline Servers

Skip the servers file and specify aliases directly in the job:

jobs.yaml
---
description: quick check
servers: [web1, db1]
tasks:
  - name: uptime
    command: uptime

Or override at the CLI:

terminal
$ ops run jobs.yaml -S web1,db1,win1

Or specify a different servers file:

terminal
$ ops run jobs.yaml -s production-servers.yaml
Priority: CLI -S overrides -s overrides the job file's servers field.
