Job Files

A job file is a YAML file that defines what to run, where to run it, and in what order. Each task runs on all applicable servers before the next task begins.

Format

jobs.yaml
---
description: install nginx stack
servers: ./servers.yaml
defaults:
  interpreter: bash
vars:
  version: "1.24"
  domain: example.com
env:
  DEBIAN_FRONTEND: noninteractive
tasks:
  - name: update packages
    command: apt-get update
  - name: install nginx
    script: ./scripts/install.sh
    env:
      VERSION: "{{ .version }}"
  - name: write config
    shell: |
      cat > /etc/nginx/nginx.conf <<'EOF'
      server {
          listen 80;
          server_name {{ .domain }};
      }
      EOF
  - name: restart
    command: systemctl restart nginx

Job Fields

FieldTypeRequiredDescription
namestringnoHuman-readable job label. Falls back to the filename in ops list.
descriptionstringnoOptional longer description of the job.
serversstring or listnoPath to a servers.yaml file or an inline list of SSH aliases. Overridable via --servers or -S.
defaultsobjectnoDefault values for tasks. Supports interpreter and workdir.
varsmap<string,string>noVariables available in {{ .var }} templating within commands, shell blocks, and env values.
envmap<string,string>noEnvironment variables passed to every task unless overridden per-task. Values are rendered with Go text/template.
taskslistyesOrdered list of tasks to execute. Each task runs on all servers before the next.

Task Types

Each task uses exactly one of these fields to define what to run:

FieldDescriptionExample
command A single command string. Executed via the interpreter's -c flag. command: apt-get install -y nginx
shell An inline multi-line script block. Uploaded via SFTP and executed. shell: | with heredoc-style content
script A local file path. Uploaded via SFTP and executed on the remote server. script: ./scripts/install.sh
upload A local file path. Uploaded via SFTP to the remote dest path and not executed. upload: ./configs/nginx.conf

Using Scripts

A script task points to a local file that is uploaded to the remote server and executed by the task's interpreter. The path is resolved relative to the working directory where ops run is invoked, not relative to the job file.

Script contents are not processed through the Go text/template renderer, but command, shell, and env values are. Use env to pass templated data to a script, or a shell block if you need substitution inside the script itself.

defaults:
  interpreter: bash
vars:
  app_version: "1.24"
tasks:
  - name: deploy
    script: ./scripts/deploy.sh
    env:
      APP_ENV: production
      APP_VERSION: "{{ .app_version }}"

Task Fields

FieldTypeRequiredDescription
namestringyesHuman-readable task label.
commandstringone ofSingle command string.
shellstringone ofInline multi-line script.
scriptstringone ofLocal file path to upload and execute.
uploadstringone ofLocal file path to upload without executing.
deststringwith uploadFull remote file path to write the uploaded file to.
interpreterstringnoOverride the job default interpreter. One of bash, sh, zsh, powershell, pwsh.
workdirstringnoOverride the job default working directory. The task runs with this as its current directory.
timeoutstringnoPer-task timeout (e.g. "30s", "5m").
ignore_errorsboolnoIf true, a non-zero exit does not stop the run.
serverslistnoLimit this task to specific server aliases. If omitted, runs on all job servers.

Templating

Command, shell, and env values support Go text/template syntax with missingkey=error:

jobs.yaml
vars:
  version: "1.24"
  domain: example.com

tasks:
  - name: install
    command: apt-get install -y nginx={{ .version }}
  - name: upload config
    upload: ./nginx-default.conf
    dest: /etc/nginx/conf.d/default.conf
  - name: set domain
    command: sed -i "s|DOMAIN|$DOMAIN|" /etc/nginx/conf.d/default.conf
    env:
      DOMAIN: "{{ .domain }}"
Note: Missing variables cause an error, not a silent empty substitution. This prevents accidental misconfiguration.

You can also pass variables via the CLI:

terminal
$ ops run jobs.yaml --var version=1.25 --var domain=prod.example.com

Examples

Multi-platform job

jobs.yaml
---
description: check servers
servers: [linux1, win1]
tasks:
  - name: linux uptime
    command: uptime
    interpreter: bash
    servers: [linux1]

  - name: windows uptime
    command: Get-Uptime
    interpreter: powershell
    servers: [win1]

Script upload with env injection

jobs.yaml
---
description: deploy app
servers: ./servers.yaml
env:
  APP_ENV: production
vars:
  version: "1.24"
tasks:
  - name: run deploy script
    script: ./scripts/deploy.sh
    env:
      APP_VERSION: "{{ .version }}"
      RELEASE_ID: "42"

Advanced Examples

Deployment with timeouts, env, and per-task servers

jobs.yaml
---
description: deploy app with health check
servers: [web1, web2]
defaults:
  interpreter: bash
vars:
  app_version: "1.24"
  health_url: http://localhost:8080/health
env:
  APP_ENV: production
tasks:
  - name: download release
    command: curl -fsSL -o /tmp/app.tar.gz https://releases.example.com/app-{{ .app_version }}.tar.gz
    timeout: 2m
    servers: [web1, web2]
  - name: run deploy script
    script: ./scripts/deploy.sh
    env:
      APP_VERSION: "1.24"
    timeout: 5m
    servers: [web1, web2]
  - name: health check
    shell: |
      for i in {1..5}; do
        curl -f {{ .health_url }} && exit 0
        sleep 2
      done
      exit 1
    timeout: 30s
    servers: [web1, web2]
    ignore_errors: true

Database backup with a fallback

jobs.yaml
---
description: backup and verify
servers: [db1]
defaults:
  interpreter: bash
env:
  PGHOST: localhost
  PGUSER: admin
tasks:
  - name: create backup directory
    command: mkdir -p /backups/$(date +%Y%m%d)
  - name: dump database
    shell: |
      pg_dump app > /backups/$(date +%Y%m%d)/app.sql
    timeout: 5m
  - name: verify backup
    command: test -s /backups/$(date +%Y%m%d)/app.sql
  - name: alert on missing backup
    command: echo "backup verification failed"
    ignore_errors: true

Local shell script with env injection

jobs.yaml
---
description: clean up and report
servers: [web1, web2]
defaults:
  interpreter: bash
env:
  LOG_DIR: /var/log/app
  KEEP_DAYS: "7"
tasks:
  - name: run cleanup script
    script: ./scripts/cleanup.sh
    timeout: 5m

The local script is uploaded and executed on each server:

scripts/cleanup.sh
#!/usr/bin/env bash
set -euo pipefail

CUTOFF=$(date -d "now - ${KEEP_DAYS} days" +%Y%m%d)
COUNT=$(find "${LOG_DIR}" -type f -name "*.log" ! -newermt "$CUTOFF" | wc -l)

if [ "$COUNT" -gt 0 ]; then
  find "${LOG_DIR}" -type f -name "*.log" ! -newermt "$CUTOFF" -exec gzip {} \;
  echo "Compressed ${COUNT} log files older than ${KEEP_DAYS} days"
else
  echo "No old logs to clean up"
fi

PowerShell script on Windows

jobs.yaml
---
description: check disk space on windows
servers: [win1]
defaults:
  interpreter: powershell
tasks:
  - name: run disk check
    script: ./scripts/check-disk.ps1
    env:
      THRESHOLD_GB: "10"
    timeout: 2m

The PowerShell script is uploaded to the remote Windows temp directory and executed:

scripts/check-disk.ps1
$threshold = [int]$env:THRESHOLD_GB
$disk = Get-Volume -DriveLetter C
$free = [math]::Round($disk.SizeRemaining / 1GB, 2)

if ($free -lt $threshold) {
    Write-Error "Low disk space: $free GB free (threshold: $threshold GB)"
    exit 1
} else {
    Write-Output "Disk space OK: $free GB free"
}
