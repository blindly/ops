ops

The operator's runner for remote tasks. One binary. No agents.

Download the latest binary

What it does

[jobs]

Job Files

Define multi-step tasks in YAML. Each task runs a command, an inline shell script, or a local script file.

[ssh]

SSH Config Native

Server aliases reference Host entries in ~/.ssh/config. No duplicated connection details.

[sh]

Any interpreter, any script

Bash, PowerShell, Python, Node, Perl — any interpreter on the target. Run commands, inline shell blocks, or local script files with no new language to learn.

[sftp]

SFTP Delivery

Scripts are uploaded via SFTP, executed, and cleaned up. No agent to install on targets.

[pool]

Parallel Execution

Worker pool runs tasks across servers concurrently. Fail-fast or continue on error.

{{ }}

Templating

Use {{ .var }} in commands and shell blocks. Variables defined at the job level.

Why not Ansible or Puppet?

ops is not a config manager. It is a thin task runner for the servers you already have.

✓

No agent, no Python

Targets only need an SSH daemon and a shell. No runtime dependency to install or maintain.

✓

No separate inventory

Server aliases resolve directly from your ~/.ssh/config.

✓

No DSL or state

YAML job files describe one-time execution, not desired system configuration.

✓

One static binary

Cross-compiled, no install script, no package manager.

Quick start

jobs.yaml 
---
description: install nginx
servers: [web1, web2]
defaults:
  interpreter: bash
vars:
  domain: example.com
tasks:
  - name: install
    command: apt-get install -y nginx
  - name: upload config
    upload: ./nginx-default.conf
    dest: /etc/nginx/conf.d/default.conf
  - name: set domain
    command: sed -i "s|DOMAIN|$DOMAIN|" /etc/nginx/conf.d/default.conf
    env:
      DOMAIN: "{{ .domain }}"
  - name: restart
    command: systemctl restart nginx
