Getting Started

Prerequisites

  • Go 1.22+ — for building from source
  • SSH access — targets must have an SSH server running (OpenSSH on Windows for PowerShell)
  • ~/.ssh/config — server aliases must exist as Host entries
Note: ops uses your existing SSH config. If you can ssh web1 and it works, ops can reach it.

Installation

From a release:

terminal
$ curl -L -o ops https://github.com/blindly/ops/releases/latest/download/ops-linux-amd64 && chmod +x ops

Other platform binaries are on the releases page.

Or install with Go:

terminal
$ go install github.com/blindly/ops/cmd/ops@latest

Or clone and build:

terminal
$ git clone https://github.com/blindly/ops.git
$ cd ops
$ make install

Verify the install:

terminal
$ ops --help
Run shell jobs on remote servers

Usage:
  ops [command]

Available Commands:
  run         Run a job
  validate    Validate a job file

Quick Start

Create a servers.yaml listing your SSH config aliases:

servers.yaml
servers:
  - web1
  - web2

Create a jobs.yaml:

jobs.yaml
---
description: ping servers
servers: ./servers.yaml
defaults:
  interpreter: bash
tasks:
  - name: uptime
    command: uptime
  - name: disk usage
    command: df -h /

Validate and run:

terminal
$ ops validate jobs.yaml
valid
$ ops run jobs.yaml

Your First Job

A real-world example — install and configure nginx across two servers:

jobs.yaml
---
description: deploy nginx
servers: [web1, web2]
defaults:
  interpreter: bash
vars:
  domain: example.com
env:
  DEBIAN_FRONTEND: noninteractive
tasks:
  - name: install nginx
    command: apt-get install -y nginx

  - name: upload config
    upload: ./nginx-default.conf
    dest: /etc/nginx/conf.d/default.conf

  - name: set domain
    command: sed -i "s|DOMAIN|$DOMAIN|" /etc/nginx/conf.d/default.conf
    env:
      DOMAIN: "{{ .domain }}"

  - name: restart nginx
    command: systemctl restart nginx

  - name: verify
    command: curl -s -o /dev/null -w "%{http_code}" http://localhost

Run it:

terminal
$ ops run jobs.yaml --fail-fast
Tip: Use --fail-fast to abort all servers on the first failure. Without it, ops continues running tasks on remaining servers.
